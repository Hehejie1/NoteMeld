# Change Spec: 多端云端与远程客户端连接地图

## 范围与现状

- A03 目前只有功能总表，缺少云端连接、远程客户端、设备身份和授权的共同语义。
- M03/M08 使用的 Lucide 图标都存在于本地 vendor 包，但 `boxes`、`scan-line`、`cloud-off`、`pencil` 尚未列入 A04 图标目录。
- Cloud 已有 `devices`、`pairings`、`tokens`、`grants`、`relay_cursors` 及对应 API；M08 仍是仅保存在页面内存中的原型，扫码只解析短时配对码，不能建立真实连接。

## 页面简述与组件映射

- A03：先展示 Cloud/客户端连接的两条路径，再展示实体字段、状态判定、跨端职责与安全不变量；复用当前文档页的 `doc-card`、`doc-table`、`doc-badge` 和横向滚动容器。
- A04：沿用本地 Lucide Iconography 目录，补录缺失图标，不创建第二套图标资产。
- M03/M08：本次不改业务交互；A03 对它们定义未来接入契约，明确当前仅为原型。

## 数据与流程边界

- 本地 Cloud 连接配置只存展示名、HTTPS 地址、账号归属和安全存储引用；Cloud 设备身份、短时配对、设备 Token、定向 Grant 与远程会话是不同实体。
- 云端扫码用于建立云端账号/当前安装实例的设备信任；远程客户端扫码用于在已连接云端下定位 Host，之后仍须验证设备身份、建立 Grant 并进行端到端密钥协商。
- 仅地址、二维码或表单保存都不能推出在线/已授权；在线以 Cloud 心跳 TTL 为目录提示，真正可控还需有效 Grant 与可用传输。
- 桌面端和移动端对 Cloud 都是普通第三端设备，不按控制能力划分特权端。所有在线设备持续发送心跳，Cloud 将目录状态同步给同组织其他设备；离线统一进入 `offline_readonly`，恢复在线并完成同步后才重新开放写操作。
- 删除本地连接配置与撤销 Cloud 设备/Grant 必须是两种显式动作，不允许静默级联 Cloud 权限。
