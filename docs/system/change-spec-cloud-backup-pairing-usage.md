# Change Spec: Cloud 备份导出、设备模型配置与运行用量

## 当前现状

Cloud 已有 Workspace 本地/S3 备份存储、模型目录、一次性配对码和 C02 基础运行看板。备份创建后只有元数据返回，页面不能下载镜像；配对确认只返回设备已配对；看板没有存储、每日对话和 Token 用量接口。

## 本次目标

- 创建当前在线 Cloud Workspace 环境的完整 ZIP 镜像，并提供认证下载接口。
- 服务启动时可指定备份镜像目录，由启动流程恢复到运行数据目录。
- 配对码一次性、短时有效；确认成功时直接返回当前账号启用模型配置及 API Key，设备不通过 Cloud 代理调用模型。
- 提供 C02 所需的真实用量聚合接口。

## 明确不做

- C06 页面不提供恢复和删除备份按钮。
- 不把 API Key 写入审计日志、页面静态数据或普通模型列表接口。
- 不改变已有恢复/删除 API，保留其兼容性；启动恢复是新增部署入口。

## 数据与安全

- 继续使用 `workspace_backups` 记录镜像元数据，文件由 BackupStorage 管理。
- 下载必须经过当前用户 Workspace 权限校验，并限制备份 ID；响应使用附件流，不暴露内部绝对路径。
- 配对确认必须在事务内消费 pending pairing，返回的模型密钥只出现一次；有效期由配对码控制，服务端不持久化明文密钥。
- 由于用户明确要求设备直连，设备端必须负责安全保存收到的密钥；日志和后续设备列表只返回 `has_api_key`。

## 接口与测试

- `GET /v1/workspaces/{workspace_id}/backups/{backup_id}/download`
- `GET /v1/cloud/usage?days=7`
- 扩展 `POST /v1/pairings/confirm` 返回一次性 `models` 配置。
- 增加备份下载权限、路径穿越、配对重复消费、密钥不落日志和用量聚合测试。

## 最小实现与回滚

优先复用现有 `BackupStorage` 和模型加密存储；下载端为本地文件流，S3 端使用短时 presigned URL。启动恢复只在显式传入镜像目录时执行。若新接口出现问题，可停用下载/配对新字段而不影响既有会话、模型和备份创建/恢复接口。
