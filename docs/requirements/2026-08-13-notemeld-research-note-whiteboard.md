## 1. 原始需求

用户希望 NoteMeld 的“学习”不是老师式授课或一次性列出大量知识点，而是一个主动研究空间：中间持续对话，右侧是一篇可入库的研究笔记及其白板投影。用户可随时修正研究目标、切换关注节点、查看冲突论证，并把笔记选文或白板节点作为上下文带回对话。

关键确认：

- 只在研究对象存在会改变检索方向的歧义时逐个提问；不机械询问学习时长、水平或“学习对象”。
- 确认目标后先展示概览、基础定义和必要图示，不一次展示完整路径与所有材料。
- 搜索结果是候选证据，不得直接成为学习路径；需要相关性过滤、实体消歧、概念抽取、去重和关系编译。
- 右侧白板本身对应一篇标准 Note；“笔记视图 / 白板视图”只是同一内容的两种视图。
- 笔记选文或白板节点右键“添加到对话”，以结构化引用进入中间输入框。
- AI 可在回复下预测下一步动作；导航动作只切换白板焦点，研究动作才触发新检索。
- 用户确认的研究结果进入现有笔记和 Wiki 管线，后续相似调研先复用本地知识。

## 2. 背景和问题

- 当前用户：希望对一个主题做快速但可验证的知识调研的人。
- 当前场景：用户输入“了解最新 Agent 情况”“研究韩信”“比较工作流和 Agent”等开放主题。
- 当前痛点：现有学习面板直接展示节点、路径、来源和掌握状态，信息密度过高；GitHub 搜索结果会未经筛选成为路径节点；学习产物与标准笔记分离，难以复用；右侧内容不能自然引用回对话。
- 为什么现在做：学习入口已经可用，但当前体验会把“检索结果列表”误当成“可学习内容”，必须在扩大使用前修正产品模型和数据边界。

## 3. 目标结果

- 用户得到持续可修正的研究对话，而不是固定课程或一次性报告。
- 用户先看到一页可读的研究概览，再主动选择架构、关键模块、判断标准、冲突证据或案例。
- 同一研究产物同时具有笔记视图和白板视图，且笔记是唯一事实源。
- 用户可把选文或节点引用带回对话，AI 明确知道引用来自哪篇笔记、哪个节点和哪些来源。
- 经过用户确认的内容进入标准 Note/Wiki 管线，可被未来研究增量复用。

## 4. 非目标

- 不建设课堂式教学、考试、学习时长规划或强制掌握度流程作为主体验。
- 不把外部搜索结果、GitHub 仓库名或论文标题直接当作知识节点。
- 不新建第二套笔记数据库，不让白板正文成为独立事实源。
- 本轮不提供自由绘图、多人实时协作、任意节点拖拽持久化或完整画图工具箱。
- 不删除旧 LearningCanvas、掌握度和历史 JSON 的读取能力。

## 5. 当前系统事实

- 已有类似能力：HomePage 已有中间对话/右侧内容分栏；MarkdownViewer 已有文章、思维导图、Wiki 视图；Sigma 图已有缩放、平移、选中和聚焦；学习画布已持久化并有消息索引。
- 当前入口 / 页面 / API：首页 `学习` 标签调用 `POST /api/conversations/{id}/learning-canvases`，HomePage 从最新 `learning_canvas` 消息恢复右侧面板。
- 当前数据来源和写入位置：标准笔记在 SQLite `note_documents` 和 `note_results/{task_id}.json`；Wiki contribution 在 `note_results/wiki/`；旧学习画布在 `workspaces/{conversation_id}/canvases/{canvas_id}.json`。
- 当前限制：外部来源被直接转换为 `type=source` 节点；右侧完整渲染重点、图、路径、复习、来源；学习画布未绑定标准笔记；对话 payload 没有结构化引用。
- 相关 known pitfalls：不能同步完整 Wiki materialize；不能让多个事实源漂移；文件写入必须原子化；消息不能塞入完整画布；外部凭证不得回显。

## 6. 用户故事

- 作为研究者，我希望在歧义真正影响研究对象时只回答一个明确问题，以便检索不跑偏。
- 作为研究者，我希望先读概览再选择深入方向，以便控制信息负荷。
- 作为研究者，我希望在笔记与白板间切换，以便同时获得线性阅读和关系导航。
- 作为研究者，我希望将选文或节点加入对话，以便围绕证据继续提问而不是重新描述上下文。
- 作为重复研究者，我希望确认后的内容进入 Wiki，以便下次先复用本地成果。

## 7. 验收标准

1. GIVEN 学习目标存在重大歧义，WHEN 创建研究空间，THEN 对话只显示当前一个澄清问题、可选答案和补充入口，且不生成无关笔记。
2. GIVEN 目标明确，WHEN 研究完成，THEN 当前会话新增一篇标准 Note，并在右侧默认显示概览；用户可切换到白板。
3. WHEN 外部搜索返回与目标无关的仓库或论文，THEN 它不得成为白板节点或推荐起点。
4. WHEN 用户在笔记中选择文本并右键“添加到对话”，THEN 输入框出现可移除引用卡片；发送后消息 meta 和模型请求均包含有界快照与文档定位信息。
5. WHEN 用户在白板节点右键“添加到对话”，THEN 引用包含 node_id、标签、摘要快照、关联来源；不复制整张图。
6. WHEN 用户点击助手回复后的导航建议，THEN 白板切换焦点且不调用模型；点击研究建议时只填入/提交新的研究问题。
7. WHEN 研究笔记保存成功但白板或 Wiki 后处理失败，THEN 笔记仍视为成功，白板可由笔记重建，Wiki 状态独立显示失败或待处理。
8. GIVEN version=1 的旧画布，WHEN 打开历史会话，THEN 仍可读取并降级显示，不删除掌握度数据。

## 8. 输入 / 输出样例

### 输入

- `韩信`
- `我想了解最新的 Agent 情况`
- 引用“Agent 的循环包含感知、规划、执行和反馈”后提问：`这个循环在哪些场景会失败？`

### 输出

- 歧义：`你指的是西汉军事家韩信，还是《王者荣耀》角色韩信？`
- 明确目标：研究笔记的概览页 + 白板中的定义、结构、判断框架、冲突证据、案例、开放问题节点。
- 对话引用：`[研究笔记 · 核心结构] Agent 循环……`，请求中包含结构化定位和短快照。

### 反例或失败样例

- 把 `gege-circle/.github`、无关政治仓库等按搜索排名直接列为第一学习路径。
- 首屏同时展示 25 个节点、完整路径、复习队列和 12 个来源。
- 右侧白板修改后与笔记正文形成两份冲突内容。

## 9. 约束

- 平台 / 设备：源码 Web 与 Tauri 桌面共用交互；移动端仍使用内容 tab。
- 性能 / 耗时：研究请求沿用 provider 超时边界；前端不设置更短总超时。
- 隐私 / 安全：引用快照限长；API key、headers、完整 provider payload 不写消息或日志。
- 兼容性：不改 conversation mode 枚举，不新增强制数据库迁移，旧画布可读。
- 成本：一次明确目标的构建最多一次研究编译 LLM 调用；导航动作不调用模型。
- 第三方依赖：复用现有 arXiv、GitHub、Tavily/SearXNG、Sigma、Markdown 和 Wiki 管线，不新增依赖。

## 10. 边界场景

- 空数据：本地和外部均无结果时生成基础研究框架并明确“证据不足”，不伪造来源。
- 网络失败：保留本地 Wiki 和成功来源；错误以 provider 级安全信息呈现。
- 任务中断：不产生半写入 Note；已保存 Note 不因白板/Wiki 失败回滚。
- 旧数据兼容：version=1 走 legacy 投影；缺少 document_task_id 时只显示白板。
- 大数据量：首屏只显示概览和一个当前焦点；来源和节点有上限，引用快照限长。
- 并发：同会话学习构建继续使用共享锁；sidecar 写入使用路径锁和唯一临时文件。

## 14. 2026-08-14 增量：整块白板与渐进节点卡片

### 用户反馈

- 白板数据已经存在，但 Sigma 相机聚焦/重置使用了错误坐标，画面可能显示为空白。
- 白板下方固定占据一块“当前焦点”详情区，压缩了真正的画布空间。
- 用户希望节点内容在白板内按需展开，并从白板节点直接“添加到对话”，而不是把所有卡片一次铺开。

### 增量目标

1. 右侧切换到白板后，顶部切换栏以下的全部可用空间均为白板，不再使用页面级滚动容器包裹白板。
2. 节点默认保持紧凑图形和短标签；仅当前选中节点在画布内显示一张浮动摘要卡。
3. 浮动卡提供“添加到对话”，继续复用现有 `whiteboard_node` 引用契约；点击空白关闭浮层。
4. 聚焦节点使用 Sigma display 坐标；适配视图使用 Camera reset，不写死坐标。
5. 容器尺寸变化后重新 resize/refresh/fit；零关系边时使用稳定紧凑布局，并明确提示当前尚未形成关系。

### 增量非目标

- 不新增拖拽持久化、自由绘图、卡片批量展开或新的后端接口。
- 不伪造缺失的关系边；关系编译质量作为独立后端改进处理。
- 不改变 Note 是唯一正文事实源、Canvas 是关系投影的既有规则。

### 增量验收标准

- GIVEN Canvas 有节点，WHEN 打开或从笔记切回白板，THEN 节点始终位于可视区域内。
- WHEN 点击“适配白板”，THEN 相机恢复图的自动适配视图，而不是移动到固定 `(0, 0)`。
- WHEN 点击节点，THEN 画布内只展开该节点的一张摘要卡；点击空白后关闭。
- WHEN 点击浮动卡“添加到对话”，THEN 输入区增加对应 `whiteboard_node` 引用。
- GIVEN Canvas 有节点但没有边，THEN 使用紧凑布局并显示非阻塞提示，画布不得为空。
