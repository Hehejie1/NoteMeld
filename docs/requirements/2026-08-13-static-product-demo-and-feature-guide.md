# 高保真静态产品演示与功能讲解

日期：2026-08-13
作者 / Agent：Codex
状态：Implemented
关联对话 / 任务：当前 Codex 任务
关联系统文档：`docs/system/current-architecture.md`、`docs/system/product-rules.md`、`docs/system/data-model.md`、`docs/system/api-inventory.md`、`docs/system/known-pitfalls.md`

## 1. 原始需求

用户希望基于 NoteMeld 当前正式产品源码抽离一套可独立运行的纯静态演示，而不是把截图直接贴成页面：

- `docs/product/` 中的 10 张正式产品截图只作为视觉基准，用于校正静态演示与正式产品的偏差。
- 静态演示应尽量复用现有 React 页面、组件、样式和路由，隔离真实后端数据与副作用。
- 页面数据写死在演示包内；可以参考本地数据库中的真实字段形状和状态组合，但不得泄露用户原始内容、密钥、Cookie、token 或本地路径。
- 页面跳转、抽屉、标签、选择、搜索、折叠等前端交互应与正式产品一致；真实生成笔记等后端能力不执行，但可以用可重复的模拟请求展示加载、进行中、成功、失败和取消等状态。
- 各种有产品意义的状态都应被演示覆盖，而不是只展示一条 happy path。
- 用户可查看某个图标或功能区的说明；右侧抽屉需要同时解释该功能的产品需求含义和当前代码行为。
- 提供一个 shell 脚本，用户执行后可直接在浏览器中预览静态演示。

## 2. 背景和问题

- 当前用户是谁：需要演示、验收、评审或理解 NoteMeld 产品能力的产品、研发、测试及外部体验者。
- 当前场景是什么：正式产品依赖 FastAPI、SQLite、本地文件、LLM、下载器、转写器和桌面 sidecar；仅启动前端会触发后端 ready gate 和真实 API 请求，无法作为自包含产品演示。
- 当前痛点是什么：截图不能跳转和交互；重新手绘页面容易与正式样式漂移；直接使用真实产品又需要后端、配置和真实数据；功能含义散落在需求、系统文档和代码中。
- 为什么现在要做：需要一份可以直接打开、覆盖主要产品路径、视觉接近正式产品且能解释功能语义的演示载体。

## 3. 目标结果

- 目标 1：得到一套无需 NoteMeld 后端即可运行的静态演示，覆盖正式产品的主要路由和关键页面状态。
- 目标 2：演示页面优先复用正式前端结构和设计 token，并以 `docs/product/*.png` 作为桌面宽屏视觉回归基准。
- 目标 3：得到确定性的本地 mock 数据和模拟任务，使加载、空数据、待处理、运行中、成功、部分成功、失败、取消等状态可进入、可复现。
- 目标 4：得到一个功能讲解抽屉，使用户可以从当前页面查看功能的产品目的、操作含义、代码实现位置、数据来源和静态演示限制。
- 目标 5：得到一个 shell 预览入口；执行后完成必要检查、启动本地静态服务器并输出可访问地址。

## 4. 非目标

- 不运行 FastAPI、SQLite、LLM、Wiki rebuild、下载器、转写器、MCP 或 Tauri sidecar。
- 不真实生成笔记、不真实下载模型、不真实保存 Cookie/API Key、不真实迁移或删除数据。
- 不把 `docs/product/*.png` 当作页面主体或热点图实现交互。
- 不为实现演示重写正式产品视觉体系，不进行无关页面重构。
- 不承诺静态演示替代正式产品的端到端业务验收。
- 不把本地数据库中的原始用户内容、Provider 配置或其他敏感字段复制进演示数据。

## 5. 当前系统事实

- 已有类似能力：现有前端已包含正式产品页面、路由、布局、设计 token、组件和绝大部分纯前端交互；Vite 已提供 `dev`、`build` 和 `preview` 能力。
- 当前入口 / 页面 / API：
  - `frontend/src/App.tsx` 使用 React Router，公开首页为 `/`，工作区包含 `/new`、`/notes/:taskId`、`/styles`、`/wiki`、`/about` 和 `/settings/*`。
  - `frontend/src/layouts/AppLayout.tsx` 提供正式侧边栏、笔记列表、桌面/移动布局和导航。
  - 页面通过 `frontend/src/services/` 请求 conversation、note、chat、wiki、style、model、transcriber、migration、usage、monitor、MCP server 和 research search 等数据。
  - `BackendInitProvider`、`useCheckBackend` 和页面 ready gate 会阻止或推迟后端未就绪时的业务请求。
- 当前数据来源和写入位置：正式产品使用 `<data_dir>/notemeld.db`、`note_results/`、Wiki 文件、workspace canvas 和本地配置文件；静态演示不得读取或写入这些正式数据源。
- 本地数据库只读盘点：当前样本含 77 个 conversations、250 条 conversation messages 和 71 个 note documents；可观察到 conversation 的 `PENDING/SUCCESS/FAILED`，message 的 `pending/running/success/failed`，以及 Wiki 的 `pending/partial/success`。这些结果只用于确定状态矩阵，不直接复制原始内容。
- 当前截图基准：`docs/product/` 有 10 张 3840×1916 截图，覆盖公开首页、空白工作台、笔记详情、Wiki、模板列表、模板创建双抽屉、模型设置、转写设置、下载器设置和关于页。
- 当前限制：没有现成的 demo/mock transport；页面服务调用和后端 ready gate 与正式运行绑定；部分正式交互会产生删除、保存、下载、安装更新等副作用。
- 相关 known pitfalls：不得破坏桌面 backend ready gate、API wrapper、任务状态语义、Wiki 状态语义、安全脱敏、源码/CLI/桌面入口；演示逻辑必须与正式逻辑隔离，不能为了演示改变正式数据和真实调用行为。

## 6. 用户故事

- 作为产品体验者，我希望从首页进入工作台并在主要页面间跳转，以便在没有后端环境时理解完整产品结构。
- 作为产品或测试人员，我希望切换模拟任务和各种状态，以便检查加载、生成、失败、部分成功和空状态的表现。
- 作为评审者，我希望页面样式与正式产品截图和现有源码一致，以便评审对象不是脱离产品的概念稿。
- 作为新成员，我希望查看图标和功能区的说明，以便同时理解产品为什么有这个功能、用户如何使用以及代码目前如何实现。
- 作为开发者，我希望演示数据和后端访问有明确隔离，以便静态演示不会误操作本地正式数据。

## 7. 验收标准

1. GIVEN 未启动 NoteMeld 后端，WHEN 用户执行静态预览 shell 脚本，THEN 浏览器可访问演示首页，且页面不会显示 backend init 失败弹窗或向 `127.0.0.1:8483` 发起业务请求。
2. GIVEN 用户位于演示首页，WHEN 点击“进入工作台”，THEN 进入演示工作台，并可通过正式侧边栏导航到新建笔记、笔记详情、风格模板、知识库、设置和关于页面。
3. GIVEN 任一演示路由，WHEN 用户刷新或直接打开该 URL，THEN 页面仍能显示对应演示状态，不依赖服务端 history fallback 之外的业务后端。
4. GIVEN 演示数据，WHEN 用户查看状态样例，THEN 至少可观察空数据、待处理、运行中、成功、失败、取消和 Wiki partial；各状态使用正式产品已有字段语义和 UI 映射。
5. GIVEN 用户触发模拟生成，WHEN 模拟流程运行，THEN 页面按确定时序展示提交、处理、总结、保存和成功或失败结果；该流程不得调用真实生成 API、写 SQLite 或写 `note_results/`。
6. GIVEN 用户执行搜索、标签切换、折叠、选择、打开/关闭抽屉等纯前端操作，WHEN 操作完成，THEN UI 响应与正式产品组件行为一致或在说明中明确静态限制。
7. GIVEN `docs/product/*.png` 中存在对应基准页面，WHEN 在 3840×1916 或等比例视口生成截图，THEN 主布局、间距、色彩、字体层级和关键组件位置不存在肉眼明显的大范围偏差；差异需要记录原因。
8. GIVEN 用户打开功能讲解，WHEN 选择有说明的图标或功能区，THEN 右侧抽屉展示名称、用户价值、操作结果、需求依据、代码依据、依赖数据和静态演示行为。
9. GIVEN 功能没有完整需求依据，WHEN 打开其说明，THEN 抽屉明确标记“代码事实”或“待补需求”，不得编造产品意图。
10. GIVEN 本地数据库含真实用户数据和 Provider 配置，WHEN 构建演示数据，THEN 产物中不包含原始对话正文、API Key、Cookie、token、绝对用户路径或可识别的敏感 payload。
11. GIVEN 正式产品正常启动，WHEN 未启用静态演示入口，THEN 现有后端 ready gate、服务调用、桌面/浏览器路由和业务行为保持不变。
12. GIVEN shell 预览脚本运行环境缺少必要依赖或端口被占用，WHEN 启动失败，THEN 脚本输出明确错误和恢复方式，不静默失败。

## 8. 输入 / 输出样例

### 输入

- 访问 `/`，点击“进入工作台”。
- 选择一条 `RUNNING` 的模拟笔记任务。
- 在“功能讲解”模式中点击“知识库”图标，或对该功能区使用右键快捷入口。
- 点击“模拟生成”，选择成功或失败场景。

### 输出

- 工作台展示与正式产品相同的侧边栏、会话/笔记内容分栏和内容面板。
- 模拟任务按预设步骤更新，无任何真实网络业务请求。
- 右侧功能讲解抽屉示例字段：
  - 功能名称：知识库
  - 产品含义：把已编译笔记沉淀为可追溯的结构化知识关系
  - 用户操作：进入图谱，切换类型/社群视图，聚焦节点
  - 需求依据：相关 requirement 与 product rule 链接
  - 代码依据：路由、页面、组件、service 和关键状态映射路径
  - 静态限制：图数据来自本地 fixture，不执行 Wiki rebuild

### 反例或失败样例

- 直接把 `docs/product/home.png` 放进 `<img>` 并叠加透明点击区。
- 静态演示仍调用 `/api/conversations`、`/api/generate_note` 或桌面更新接口。
- 把真实数据库的 API Key、Cookie、对话原文或绝对路径提交为 fixture。
- 为打开说明而劫持正式导航图标，导致用户无法按产品路径跳转。
- 功能说明只写营销文案，不给出需求依据和代码依据。

## 9. 约束

- 平台 / 设备：优先覆盖桌面浏览器宽屏并保持现有响应式能力；视觉基准为 3840×1916 截图，至少补充一个常见 1440px 宽视口检查。
- 性能 / 耗时：静态首屏不等待后端健康检查；模拟请求时延可控且可重置；构建产物应可由普通静态服务器托管。
- 隐私 / 安全：数据库只允许只读分析字段形状和状态分布；演示 fixture 必须脱敏、合成或重写；禁止任何秘密和本地绝对路径进入产物。
- 兼容性：默认正式入口和正式 service 行为不变；演示通过显式入口、构建模式或适配层启用；不改变现有 API 契约和数据模型。
- 成本：不调用付费 LLM、搜索、下载或转写服务。
- 时间：已于 2026-08-13 完成实现与聚焦验收。
- 第三方依赖 / License：优先复用现有依赖，不为 mock 或截图回归引入重量依赖，确需新增时在实施计划说明用途和许可。

## 10. 边界场景

- 空数据：提供无笔记、无 Wiki 节点、无模型、无模板或无用量等可进入状态。
- 权限拒绝：文件选择、剪贴板、外链和桌面专属操作在静态演示中显示安全提示或模拟结果。
- 网络失败：所有模拟请求可选择失败；不依赖真实网络获得业务数据。Google Fonts 等外部展示资源需要有系统字体降级。
- 任务中断：模拟生成支持取消或重置，不留下跨刷新不可控的定时器状态。
- 旧数据兼容：不迁移、不修改真实旧数据；fixture 可包含历史状态映射样例。
- 大数据量：侧边栏、Wiki 图、用量记录应包含足以暴露滚动和密度问题的样本量，但不能因追求数量导致产物膨胀。
- 直接路由：静态服务器应支持 history fallback，或演示构建使用适合静态托管的路由策略。
- 说明缺失：功能仍可使用；抽屉标记资料缺口，不阻断页面。
- 破坏性操作：删除、迁移导入、模型下载、更新安装等只改变当前演示内存或给出模拟确认，不接触本地正式数据。

## 12. 与系统事实的冲突检查

- 是否和 `product-rules.md` 冲突：不冲突。演示保持 Structured Intelligence 视觉、来源可追溯和正式运行入口；不改变“AI 编译知识，人验证和消费”的产品范式。
- 是否和 `data-model.md` 字段语义冲突：不冲突。fixture 复用字段语义但不写真实 SQLite/文件；状态样例需保持 task、conversation、message、document 和 Wiki 状态边界。
- 是否和 `api-inventory.md` 接口语义冲突：不冲突。静态模式模拟现有 service 契约，不新增或修改后端 API；正式模式继续使用 `{code,msg,data}` 和既有调用路径。
- 是否会重新引入 `known-pitfalls.md` 中的问题：主要风险是绕过 ready gate、破坏状态语义、泄露凭证、把演示逻辑混入正式服务调用。通过显式演示边界、只读数据分析、fixture 审查和正式模式回归防止。
- 是否影响本地数据或线上服务：设计目标为零影响；静态演示不读取运行时数据库、不写业务目录、不调用线上业务服务。
- 是否影响用户已确认交互：正式入口不受影响；演示页面保留正式点击语义，并采用已确认的“讲解模式 + 右键快捷入口”。
