# NoteMeld 多端会话、云端 Agent 与设备协同

日期：2026-08-29  
状态：Clarifying（商用安全评审后）  
作者 / Agent：Codex  
关联系统文档：`current-architecture.md`、`product-rules.md`、`data-model.md`、`api-inventory.md`、`known-pitfalls.md`

## 1. 产品目标

在同一个 NoteMeld 产品中提供三种运行模式：

1. **本地会话**：Agent、workspace、模型、Skill、插件、Application 和数据均在当前设备。
2. **云端原生会话**：Agent 在云端统一 workspace 中运行，桌面、移动端和 Web 作为查看与控制端。
3. **设备远程会话**：一台设备通过端到端加密连接另一台宿主设备，由宿主本地 Agent、模型、Skill、插件和 Application 执行；云端只承担注册、信令和密文中转。

附件截图仅作为“选择本地或远程项目”的视觉参考，不构成额外业务规则。

## 2. 用户身份与设备身份

- 不使用邮箱、手机号或第三方登录。
- 本地 NoteMeld profile 的用户名只是设备内显示信息，与云端登录无关。
- 云端部署启动时通过环境变量初始化一个 bootstrap 超管账户；超管登录管理后台，创建、编辑、禁用和删除普通云端用户。普通用户使用超管分配的云端登录用户名+密码进入后台；云端登录用户名在该云端实例内唯一。
- 云端为每个用户签发类似 Git Personal Access Token 的账户 token；密码只保存不可逆哈希，token 只保存哈希并绑定 audience/scope/expiry/jti。
- 每台设备拥有分布式唯一 `device_id` 和独立设备身份；不同平台可以使用不同生成方式，但必须有碰撞防护、持久性和重装/迁移语义。设备 ID 不是安全凭证，必须绑定设备公钥并支持重装视为新设备。
- token 在设备安全存储中保存；全部配置、会话、消息和控制接口通过 TLS，远程会话 payload 另加 E2EE。
- 必须支持 token/设备凭证的轮换、撤销、过期和恢复密钥/已授权设备恢复。

## 3. 会话和空间语义

### 3.1 本地会话

- 用户选择本地文件夹作为 workspace。
- 会话、压缩摘要、事件、长期记忆和 workspace 文件保存在宿主设备。
- 使用宿主设备的模型、MCP、Skill、插件和 Application。

### 3.2 分享为云端原生会话

- “分享到云端”不是把原会话变成双向镜像，而是在云端统一 workspace 中创建一个全新会话。
- 完整复制历史、压缩摘要、事件、会话空间文件、长期记忆和非敏感模型/MCP 配置。
- 不复制设备本地 secret、Skill、插件包或 Application 包。
- 云端缺少原会话使用过的工具时，保留工具记录并显示“当前云端不可用”，不得伪装成可执行。
- 云端原生会话由云端 Agent runtime 执行；桌面、移动端和 Web 可查看、发送消息和处理允许的审批。

### 3.3 设备远程会话

- 任意设备之间支持双向远程控制，不限定“手机控制电脑”。
- 会话正文、摘要、文件内容和事件由宿主设备向控制设备按需同步；云端不保存消息或会话正文，只做 E2EE 信令/实时中转。
- 宿主离线时不允许发送远程消息；发送失败必须立即返回控制端。云端不保存未送达消息。
- 已被宿主接收的后续队列存储在宿主设备，由宿主 queue authority 顺序执行。
- 控制端不能使用自己的 Skill、插件或 Application 替代宿主能力；所有执行能力取自宿主设备。
- 用户进入会话时主动请求宿主最新 snapshot，之后订阅实时事件；不要求云端维护长期会话副本。

## 4. 完整同步边界

默认同步：会话元数据、全部消息与 Agent event、压缩信息、workspace 文件、长期记忆、模型非敏感配置、MCP 非敏感配置、工具调用记录、审批记录、任务状态和 provenance。

默认不同步：API key、token、Cookie、私有环境变量、设备专属密钥、Skill 内容、插件包、Application 包及它们的本地私有数据。

远程或云端缺少依赖能力时：展示能力名称、来源设备和不可用原因；点击不执行。MCP endpoint 若只在原设备可访问，应按“宿主可用/当前环境不可用”显示。

## 5. 会话队列、分支、收纳与删除

- 每个会话是一个串行 mailbox；多个设备同时发送消息时，由会话 authority 分配严格递增序号并排队。
- 同一时间一个会话最多执行一个 active Turn；后续消息处于 `queued`，前一 Turn 终结后再执行。
- 本地/远程会话的队列 authority 在宿主设备；云端原生会话的 queue authority 在云端 runtime。
- 复制分支创建完全独立的新会话，复制当时全部可复制内容；运行时不维持父子同步关系。
- “收纳”将会话移动到独立列表并在当前设备主列表隐藏，支持恢复。
- “删除”是硬删除；硬删除的 authority、跨设备传播和恢复宽限期仍待确认。

## 6. 设备控制权限

### 默认权限

- 发送消息。
- 选择宿主允许暴露的文件上下文和模型。
- 调用宿主设备工具。
- 危险操作必须在宿主设备审批。

### 超管权限

- 包含默认权限。
- 危险操作可由控制端审批。
- 可把会话权限提升为“允许完全访问”。

每个授权必须绑定控制设备、宿主设备、scope、workspace、有效期和撤销状态；超管授权需要二次确认并留下审计记录。

## 7. 离线、暂停与恢复

- 宿主离线后，active Turn 进入 `pause_requested/paused|interrupted`，该会话禁止接收新的可执行消息。
- 队列和最后确认事件必须保留；重新连接或重启后，用户选择“继续原任务”或“终止原任务并处理下一条排队消息”。
- 未知状态的非幂等工具调用不得自动重放，必须进入 `needs_attention`。
- “暂停”是协作式 checkpoint，已经进入系统调用或外部副作用的操作不能保证瞬时冻结。
- 远程控制采用“局域网优先直连、云端 relay 兜底的 E2EE remote control”：先通过云端认证后的设备发现尝试同一局域网连接，失败再通过云端实时 relay；两条路径使用同一 E2EE session。未送达消息不落云端，宿主设备只保存已接收的 command queue。relay 禁止请求体日志、APM body 采集、崩溃 dump 和持久化录制。

## 8. Application 跨端关联

- Application 仍按平台独立安装，不作为会话同步内容。
- 可配置 `ApplicationAssociation`，把桌面 Application 与 iOS/Android/Harmony/Web 的对应 Application 关联。
- 远程会话引用宿主 Application 时：未关联则只展示不可操作记录；有关联且控制端已安装兼容版本时，可打开控制端对应 Application 查看同步后的允许数据/Artifact。
- Skill/插件在非宿主设备只展示，不响应点击，也不得在控制端本地执行。

## 9. 工程目录边界

所有端工程位于 NoteMeld 仓库独立目录：`cloud/`（云端）、`desktop/`（Windows/macOS/Linux）、`frontend/`（Web/桌面 UI）、`backend/`（本地 Host）、`android/`、`ios/`、`harmony/`。云端与桌面 Agent 复用独立 `notemeld-agent-sdk`、事件协议、队列语义和 capability contract；通过注入不同的 workspace、模型、secret 和工具 provider 复用 Agent 对话逻辑，不复制桌面文件系统或桌面权限实现。

## 10. 验收标准

1. 无邮箱/手机号时，用户可通过云端 `account_id/login handle` + 密码、账户 token 和设备身份完成连接；撤销设备后所有新请求稳定失败。
2. 本地会话分享到云端后创建全新云端 session，完整复制允许内容，原本地会话继续独立存在。
3. 远程会话正文经过 E2EE，relay 无法读取明文；控制端可按需获取最新 snapshot 并订阅后续事件。
4. 多设备向同一会话发送消息时严格排队，不并行启动两个 Turn。
5. 宿主离线时 active Turn 停止推进、队列保持且拒绝新执行；恢复后由用户选择继续或跳过。
6. 默认权限下危险操作只能在宿主审批；超管权限明确授权后可在控制端审批。
7. Skill/插件/Application 不随会话复制；缺少能力时准确展示不可用状态。
8. 收纳只影响指定设备的列表可见性；硬删除行为按最终 authority 规则执行。

## 11. 已解决的关键边界

1. 云端职责拆分为 cloud-native Agent 服务和 P2P remote relay；前者允许云端执行时读取数据，后者不保存明文或未送达消息。
2. 远程宿主离线时控制端发送失败；已接收队列仅保存在宿主设备。
3. 设备 ID 可按平台选择实现，只要求分布式唯一、持久和可撤销。
4. 账号使用用户名/密码 + token；接受恢复密钥或已授权设备恢复。
5. 远程会话宿主负责硬删除，云端原生会话云端负责硬删除，不设 7 天撤销期。
6. 他人通过带权限/有效期的 share token 加入。
7. 接受 checkpoint 协作式暂停和 `needs_attention`。
8. 云端 workspace 使用单独的云端 secret 配置，不复制本地 secret。

## 12. 已确认的实现决策

- 云端第一版使用 FastAPI。
- 云端服务与本地 `backend/` 前期物理分开，不共享 Python domain package；通过 HTTP/JSON、E2EE relay 协议和独立 `notemeld-agent-sdk` artifact 复用契约。后续再评估抽取共享库。
- 云端 workspace 默认使用云端服务本地磁盘；路径通过云端部署配置注入，不能写入代码包目录。
- 云端 workspace 支持查看磁盘用量、容量告警、原子写入/崩溃恢复状态、备份/恢复和数据迁移状态；本地文件夹默认可读，写入、删除和执行必须经过用户授权。
- 云端 workspace 支持查看磁盘用量、容量告警、原子写入/崩溃恢复状态、备份/恢复和数据迁移状态；本地文件夹默认可读，写入、删除和执行必须经过用户授权。
- 云端部署支持环境变量配置 bootstrap 管理员账号和密码；密码仅用于启动初始化/管理登录，运行时保存不可逆哈希，禁止出现在日志和 API 响应。
- 用户用户名不要求唯一，只作标识；账户唯一性使用 `account_id`，设备唯一性使用 `device_id`。
- share token 的有效期（可永久）与权限角色独立配置；token 可只读、默认控制或超管，二者互不隐式绑定。
- 第一期目标是所有端完成主体工程骨架和最小协议闭环联调，不做公网正式上线。

## 13. 商用安全与稳定性评审结论

当前产品方向可行，但在以下 P0 门禁完成前不得宣称商用安全：成熟 E2EE 握手/设备认证/密钥轮换；账户主体不依赖非唯一用户名；远程危险操作 allowlist、沙箱和宿主 kill switch；queue lease/fencing 和事件 cursor 幂等；relay 的实时送达/断线竞态；云端租户隔离、备份恢复、配额和审计。公网 Beta 前还必须补齐负载/混沌测试、MCP SSRF 防护、备份删除、供应链签名和移动端后台恢复。

## 14. 非阻塞待办

1. 不同平台 device_id 的具体算法和重装迁移 UX。
2. 云端本地磁盘迁移、备份和容量告警策略。
3. share token 默认有效期和最大控制设备数的产品默认值。
